## Worth studying

- [Bridging Latent and Explicit Reasoning with Looped Transformers](https://arxiv.org/abs/2606.31779) — Fan/Svete/Lee: the clearest answer to "why has latent chain-of-thought underperformed, and can it be fixed?" Latent CoT (reason in continuous hidden states, skip decoding) is efficient but LOSES to explicit CoT beyond ~1B params and the gap WIDENS with scale; looped / recurrent-depth Transformers (reuse weights to add depth without parameters) are the natural substrate, and a simple K-latent-block looped recipe closes the gap. The scaling-honest reference for the looped/latent-reasoning line (with LT2, Ouro, LoopCoder-v2, PoLar)
- [AI-Infra-Guard: Multi-Layer Agent Red Teaming](https://arxiv.org/abs/2606.31227) — Yong Yang et al. (10 authors): an open-source blueprint for the agent-security stack. Its observation is that the attack surface is STRATIFIED — infrastructure, protocol/tool (MCP servers, agent-skill packages), agent behavior, and the model — and no single detection paradigm covers all, so it matches a technique to each layer (1,400+ vuln rules; agentic MCP/skill auditing; multi-turn black-box red teaming; a 26-operator jailbreak harness). The tool-shaped instance of the "security into the architecture / defense-in-depth" thesis, and a checklist of what each layer of a deployed agent needs tested
- [SkillOpt: Agent skills as trainable parameters](https://www.microsoft.com/en-us/research/blog/skillopt-agent-skills-as-trainable-parameters/) — Microsoft Research: the cleanest statement of "make the skill file itself trainable." Instead of hand-editing an agent's SKILL.md or fine-tuning the model, SkillOpt treats the skill file as a trainable parameter OUTSIDE a frozen model, optimized as a controlled process (bounded text edits, validation gating, rejected-edit feedback, slow/meta updates against prompt drift). Best/tied-best in all 52 eval cells, no weight updates, and skills transfer across model scales and harnesses — the weight-free counterpart to the compile-behavior-into-adapters line
- [Memora: A Harmonic Memory Representation](https://www.microsoft.com/en-us/research/blog/memora-a-harmonic-memory-representation-balancing-abstraction-and-specificity/) — Microsoft Research: a clean design for agent long-term memory that decouples WHAT is stored (rich content) from HOW it is retrieved (lightweight abstractions + cue anchors). New SOTA on LoCoMo/LongMemEval, beating Mem0/RAG/full-context at up to 98% fewer context tokens — the current reference for "retain and access over time" without re-feeding context each turn
- [PrismML Ternary Bonsai (true 1.58-bit LLMs at 8B/4B/1.7B)](https://prismml.com/news/ternary-bonsai) — a commercial, independent (Caltech-origin) lab shipping a ternary-throughout LLM family: {-1,0,+1} weights in EVERY layer (embeddings, attention, MLPs, LM head — "no higher-precision escape hatches"), group-wise {-s,0,+s} with a shared FP16 scale per 128 weights, ~9× smaller memory than 16-bit. The clearest current existence proof of true 1.58-bit models ABOVE the ~2.4B research ceiling. Honest caveat: benchmarks are vendor-claimed and weights are vendor-hosted (download availability unverified)
- [Program-as-Weights (PAW): compiling fuzzy functions into local adapters](https://arxiv.org/abs/2607.02512) — the practical face of the parametric-injection axis: everyday tasks (alert on important log lines, repair malformed JSON, rank by intent) are "fuzzy functions" that resist clean rules and get outsourced to LLM APIs at the cost of locality, reproducibility and price. PAW compiles such a function from a natural-language spec into a compact local adapter (a 4B compiler trained on the released 10M-example FuzzyBench emits a PEFT adapter for a frozen lightweight model). "Put the behavior in weights, not the prompt"
- [Ponytail (Claude Code skill: agents that write less code)](https://github.com/DietrichGebert/ponytail) — a daily-driver skill that steers coding agents toward a "lazy senior dev" discipline (YAGNI, stdlib before custom code, native platform features before dependencies), backed — unusually for a viral prompt-hack — by a reproducible promptfoo benchmark: real headless Claude Code sessions editing a real repo → −54% LOC mean (up to −94% on over-build traps), −22% tokens, −20% cost, 100% safe. Study it for the token/cost lever AND the honest self-benchmark methodology
- [TRIAGE: Role-Typed Credit Assignment for Agentic RL](https://arxiv.org/abs/2606.32017) — the cleanest statement of the agentic-rl-credit-017 axis: standard GRPO spreads the final verifier outcome as a UNIFORM advantage over every action token ("structurally incomplete"), so a search, a click and an edit get identical credit; TRIAGE assigns role-typed credit to environment-facing action classes. The reward/credit-side complement to on-policy distillation and verifiable environments (pair with QVal 2606.32034 + ECHO 2606.29745)
- [Senior SWE-Bench (Snorkel AI)](https://senior-swe-bench.snorkel.ai) — a deployment-grounded coding-agent benchmark on the premise "we treat agents like senior engineers, so why evaluate them like junior ones?": under-specified natural-language tasks (a validation agent writes adaptive behavioral tests), bug tasks from real PRs needing runtime investigation, and scoring that rewards "tasteful" solves against unstated codebase practices. Study it before trusting SWE-bench-style leaderboards for agent readiness
- [DOPD: Dual On-policy Distillation](https://arxiv.org/abs/2606.30626) — on-policy distillation trains a student on its OWN rollouts under dense token-level teacher signals; DOPD's contribution is a warning — infusing privileged information induces a *privilege illusion* (the student conflates the transferable capability gap it should close with an information-asymmetry gap it can only mimic). A concrete design constraint for distillation pipelines (pair with OPID 2606.26790, AsyncOPD 2606.24143, and the remedy DemoPSD 2607.02502)
- [Agentic Abstention: Do Agents Know When to Stop Instead of Act?](https://arxiv.org/abs/2606.28733) — agentic abstention is sequential (answer / abstain / gather-more per turn), so the metric that matters is not WHETHER an agent can abstain but WHEN. Across web-shopping, terminal and QA (28K+ tasks, 13 systems), some agents never stop, others burn wasted tool calls — study it before trusting any long-horizon agent loop in production
- [Experience Graphs / Trellis: The Data Foundation for Self-Improving Agents](https://arxiv.org/abs/2606.29823) — a 25-author argument that long-horizon agentic work is a database WORKLOAD: the "experience graph" an agent produces (artifacts, tool outputs, rewards, sibling comparisons, causal lineage) is thrown away as JSON checkpoints today; Trellis treats it as first-class, governed, queryable state — the systems lens consolidating the agent-runtime-015 axis
