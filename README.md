## Worth studying

- [Program-as-Weights (PAW): compiling fuzzy functions into local adapters](https://arxiv.org/abs/2607.02512) — the practical face of the new parametric-injection axis: many everyday tasks (alert on important log lines, repair malformed JSON, rank by intent) are "fuzzy functions" that resist clean rules and get outsourced to LLM APIs at the cost of locality, reproducibility and price. PAW compiles such a function from a natural-language spec into a compact, locally-executable neural artifact — a 4B compiler (trained on the released 10M-example FuzzyBench) emits a parameter-efficient adapter for a frozen lightweight model. Study it as "put the behavior in weights, not the prompt" (alongside Skill-to-LoRA and DMoE), and for FuzzyBench + the compiler recipe as a reusable pattern for cheap, reproducible local replacements for LLM-API glue
- [Ponytail (Claude Code skill: agents that write less code)](https://github.com/DietrichGebert/ponytail) — a daily-driver skill that steers coding agents toward a "lazy senior dev" discipline (YAGNI, stdlib before custom code, native platform features before dependencies, one line before fifty), and — unusually for a viral prompt-hack — backs it with a reproducible promptfoo benchmark: real headless Claude Code sessions editing a real repo, fair arms, median-of-n, git-diff LOC + adversarial safety-exec → −54% LOC mean (up to −94% on over-build traps), −22% tokens, −20% cost, 100% safe. Study it for the token/cost lever AND for the honest self-benchmark methodology
- [TRIAGE: Role-Typed Credit Assignment for Agentic RL](https://arxiv.org/abs/2606.32017) — the cleanest statement of the new agentic-rl-credit-017 axis: standard GRPO spreads the final verifier outcome as a UNIFORM advantage over every action token ("structurally incomplete"), so a search, a click and an edit get identical credit; TRIAGE assigns role-typed credit to environment-facing action classes. The reward/credit-side complement to on-policy distillation and verifiable environments (pair with QVal 2606.32034 + ECHO 2606.29745)
- [Senior SWE-Bench (Snorkel AI)](https://senior-swe-bench.snorkel.ai) — a deployment-grounded coding-agent benchmark on the premise "we treat agents like senior engineers, so why evaluate them like junior ones?": under-specified natural-language tasks (a validation agent writes adaptive behavioral tests), bug tasks from real PRs needing runtime investigation, and scoring that rewards "tasteful" solves against unstated codebase practices. Study it before trusting SWE-bench-style leaderboards for agent readiness
- [DOPD: Dual On-policy Distillation](https://arxiv.org/abs/2606.30626) — on-policy distillation trains a student on its OWN rollouts under dense token-level teacher signals; DOPD's contribution is a warning — infusing privileged information induces a *privilege illusion* (the student conflates the transferable capability gap it should close with an information-asymmetry gap it can only mimic). A concrete design constraint for distillation pipelines (pair with OPID 2606.26790, AsyncOPD 2606.24143)
- [Agentic Abstention: Do Agents Know When to Stop Instead of Act?](https://arxiv.org/abs/2606.28733) — agentic abstention is sequential (answer / abstain / gather-more per turn), so the metric that matters is not WHETHER an agent can abstain but WHEN. Across web-shopping, terminal and QA (28K+ tasks, 13 systems), some agents never stop, others burn wasted tool calls — study it before trusting any long-horizon agent loop in production
- [Experience Graphs / Trellis: The Data Foundation for Self-Improving Agents](https://arxiv.org/abs/2606.29823) — a 25-author argument that long-horizon agentic work is a database WORKLOAD: the "experience graph" an agent produces (artifacts, tool outputs, rewards, sibling comparisons, causal lineage) is thrown away as JSON checkpoints today; Trellis treats it as first-class, governed, queryable state — the systems lens consolidating the agent-runtime-015 axis
- [LongCat-2.0 (Meituan, 1.6T/48B MoE)](https://huggingface.co/meituan-longcat/LongCat-2.0) — an 8th lab's frontier open-weight MoE announcement, notable for its TRAINING substrate: the full 1.6T run (>35T tokens) was done ENTIRELY on AI ASIC superpods (non-NVIDIA) — an existence proof that frontier-scale pretraining is now viable off the CUDA stack, plus "LongCat Sparse Attention" for 1M ctx. Caveat: weights "coming soon"
- [Agents-A1: Scaling the Horizon, Not the Parameters](https://arxiv.org/abs/2606.30616) — a 35B MoE agentic model reaching "trillion-parameter-level" agent performance by scaling the AGENT HORIZON (45K-token-avg trajectories) via a 3-stage recipe ending in multi-teacher on-policy distillation; the thesis that horizon/data infrastructure + distillation can substitute for raw scale in agents
- [SGLang v0.5.14 release notes](https://github.com/sgl-project/sglang/releases/tag/v0.5.14) — one serving-engine release absorbing much of the frontier open-weight + subquadratic-attention class at once: native DeepSeek Sparse Attention, Nemotron-H Mamba2-hybrid DP-attention + MTP, a Mamba radix-cache, a Kimi-Linear CuteDSL prefill kernel, plus native GLM-5.2 / Kimi-K2.7-Code / LFM2.5 / DiffusionGemma. A map of what serving engines must build for sparse/linear/hybrid-attention MoEs
- [A First Comprehensive Study of TurboQuant (vLLM)](https://blog.vllm.ai/2026/05/11/turboquant.html) — the vLLM team's honest production benchmark of TurboQuant KV-cache quantization vs BF16/FP8: low-bit KV-quant is NOT a throughput win (FP8 matches BF16 at negligible cost); TurboQuant only pays off as a memory-CAPACITY lever, cutting burst TTFT ~5×. Read before reaching for KV-quant in serving
- [DiffusionGemma: The First dLLM Natively Supported in vLLM](https://blog.vllm.ai/2026/06/10/diffusion-gemma.html) — vLLM's writeup of integrating a discrete-diffusion LM into an autoregressive-first engine via a native `DiffusionSampler` + reusable `ModelState`, with `vllm bench serve` throughput on H100/H200; the reference for what serving a non-autoregressive LM requires
- [Accelerating Gemini Nano with frozen Multi-Token Prediction](https://research.google/blog/accelerating-gemini-nano-models-on-pixel-with-frozen-multi-token-prediction/) — retrofit MTP onto a FROZEN production model (Gemini Nano v3) so one model both generates and self-drafts — speculative-decoding-style speedups WITHOUT a separate drafter, now on Pixel 9/10
- [The Verification Horizon: No Silver Bullet for Coding Agent Rewards](https://arxiv.org/abs/2606.26300) — "verifying is easier than producing" is breaking down for coding agents: generating complex solutions outpaces our ability to verify them, so reward *verification* becomes the bottleneck; the motivating diagnosis for the agentic-rl-credit-017 axis, read before trusting any RLVR pipeline
