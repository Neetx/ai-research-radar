## Worth studying

- [Bridging the Gap Between Latent and Explicit Reasoning with Looped Transformers](https://arxiv.org/abs/2606.31779) — Ying Fan, Anej Svete, Kangwook Lee: the clearest current answer to "why has latent chain-of-thought underperformed, and can it be fixed?" Latent CoT (reason in continuous hidden states, skip decoding tokens) is more efficient but LOSES to explicit CoT beyond ~1B params, and the gap WIDENS with scale — so cheap latent reasoning has stayed mostly theoretical. This paper argues looped / recurrent-depth Transformers (reuse weights to add computation depth without parameters) are the natural substrate and gives a simple recipe — a looped padded Transformer processing K latent blocks — that closes the gap. Study it as the scaling-honest reference for the looped/latent-reasoning line (with LT2, Ouro, LoopCoder-v2, PoLar): it names the failure mode precisely and shows the architectural fix, and pairs with two same-fortnight looped-transformer results (Stabilizing-Extrapolation 2606.29983 on loop-count OOD variance; DiscoLoop 2607.00341 on multi-hop).
- [AI-Infra-Guard: Multi-Layer Agent Red Teaming](https://arxiv.org/abs/2606.31227) — Yong Yang et al. (10 authors): a practical, open-source blueprint for the agent-security stack. Its load-bearing observation is that an AI agent's attack surface is STRATIFIED — infrastructure, protocol/tool (MCP servers, agent-skill packages), agent behavior, and the model itself — and no single detection paradigm covers all layers, so it deliberately matches a different technique to each: deterministic rule-matching over 75+ AI components / 1,400+ vuln rules (infra), LLM-driven agentic auditing of MCP servers and skill packages (protocol), multi-turn black-box red teaming (behavior), and a jailbreak harness of 26+ operators over 16 datasets (model). Study it as the concrete, tool-shaped instance of the "security must move into the architecture / defense-in-depth" thesis (agent-security-004) — and as a checklist of what each layer of a deployed agent actually needs tested (note especially the MCP-server + agent-skill supply-chain audit layer).
- [SkillOpt: Agent skills as trainable parameters](https://www.microsoft.com/en-us/research/blog/skillopt-agent-skills-as-trainable-parameters/) — Microsoft Research: the cleanest current statement of "make the skill file itself trainable." Instead of hand-editing an agent's SKILL.md (no guarantee it helps) or fine-tuning the model, SkillOpt treats the skill file as a trainable parameter OUTSIDE a frozen model and optimizes it as a controlled process — bounded text edits, validation gating, rejected-edit feedback, slow/meta updates to prevent prompt drift. Best-or-tied-best in all 52 eval cells (6 benchmarks × 7 models × 3 modes) with NO weight updates, and the optimized skills transfer across model scales and harnesses. Study it as the weight-free counterpart to the compile-behavior-into-adapters line — how to make an agent's context/skills improve like a trained artifact.
- [Memora: A Harmonic Memory Representation](https://www.microsoft.com/en-us/research/blog/memora-a-harmonic-memory-representation-balancing-abstraction-and-specificity/) — Microsoft Research: a clean design for agent long-term memory that decouples WHAT is stored (rich content) from HOW it is retrieved (lightweight abstractions + cue anchors), balancing abstraction and specificity. New SOTA on LoCoMo and LongMemEval, beating Mem0, RAG and full-context inference while using up to 98% FEWER context tokens — read it before building any long-horizon agent memory layer, as the current reference for "retain and access over time" without re-feeding context each turn.
- [PrismML Ternary Bonsai (true 1.58-bit LLMs at 8B/4B/1.7B)](https://prismml.com/news/ternary-bonsai) — a commercial, independent (Caltech-origin) lab shipping a ternary-throughout LLM family: {-1,0,+1} weights in EVERY layer (embeddings, attention, MLPs, LM head — "no higher-precision escape hatches"), group-wise {-s,0,+s} with a shared FP16 scale per 128 weights, ~9× smaller memory than 16-bit. Study it as the clearest current existence proof of true 1.58-bit models ABOVE the ~2.4B research ceiling (BitNet's largest public ternary checkpoint) — a commercial vendor claiming an 8B and 4B ternary model that outperforms same-class peers, building on its earlier "1-bit Bonsai" (prismml.com/news/bonsai-8b). Read it for the ternary-throughout design choices (uniform 1.58-bit including the LM head) as the aggressive edge of the low-bit/on-device axis; honest caveat: benchmarks are vendor-claimed and weights are vendor-hosted (download availability unverified)
- [Program-as-Weights (PAW): compiling fuzzy functions into local adapters](https://arxiv.org/abs/2607.02512) — Wentao Zhang, …, Stuart Shieber (Harvard-line): the cleanest instance of the new parametric-injection-018 axis and a genuinely practical paradigm. Many everyday tasks — alert on important log lines, repair malformed JSON, rank results by intent — are "fuzzy functions" that resist clean rules and get outsourced to LLM APIs at the cost of locality, reproducibility and price. PAW compiles such a function FROM a natural-language spec INTO a compact, locally-executable neural artifact: a 4B compiler (trained on the released 10M-example FuzzyBench) emits a parameter-efficient adapter for a frozen, lightweight model. Study it as the "put the behavior in weights, not the prompt" alternative to RAG / harness-context (alongside Skill-to-LoRA's skill→adapter and DMoE's knowledge→MoE), and for the FuzzyBench dataset + compiler recipe as a reusable pattern for shipping cheap, reproducible local replacements for LLM-API glue code
- [Ponytail (Claude Code skill: agents that write less code)](https://github.com/DietrichGebert/ponytail) — DietrichGebert; a practical daily-driver skill for anyone using coding agents. It steers the agent toward a "lazy senior dev" discipline — question whether the task needs to exist (YAGNI), reach for the standard library before custom code, native platform features before dependencies, one line before fifty — and, unusually for a viral prompt-hack, backs the claim with a REPRODUCIBLE promptfoo benchmark: real headless Claude Code sessions editing a real public repo (full-stack-fastapi-template), fair arms (baseline / terse-prose "caveman" / ponytail / a plain "YAGNI + one-liners" prompt), median-of-n reported, git-diff LOC + adversarial safety execution. Result: −54% LOC mean (up to −94% where the agent would over-build, e.g. a date picker 404→23 lines by reaching for a native `<input>`), −22% tokens, −20% cost, −27% time, and 100% safe (vs the one-liner prompt that dropped a path-traversal guard once). Study it for the token/cost lever it gives coding-agent users AND as a rare example of a community skill measuring itself honestly — the benchmark methodology (headless-agent diffs + safety-exec, not bare-model prompting) is itself worth copying
- [TRIAGE: Role-Typed Credit Assignment for Agentic RL](https://arxiv.org/abs/2606.32017) — Yuanda Xu et al. (8 authors): the cleanest statement of the problem the new agentic-rl-credit-017 axis tracks. Standard GRPO takes the final verifier outcome and spreads it as a UNIFORM advantage over every action token in the trajectory — "useful but structurally incomplete" — so a search, a click, an edit and a navigation command all get identical credit regardless of which actually mattered. TRIAGE assigns role-typed credit to environment-facing action CLASSES instead. Study it (with QVal 2606.32034 on cheaply evaluating dense supervision, ECHO 2606.29745 on turn-level credit, and the Verification-Horizon / Multi-Step-Collapse diagnoses) as the current front of "outcome rewards are too sparse for long-horizon agents — assign credit at a finer grain"; it is the reward/credit-side complement to on-policy distillation (dense token-level teacher signal) and verifiable environments (rl-env-005)
- [Senior SWE-Bench (Snorkel AI)](https://senior-swe-bench.snorkel.ai) — a deployment-grounded coding-agent benchmark built on the premise "we treat agents like senior engineers, so why evaluate them like junior ones?" Feature tasks use realistic, UNDER-specified natural-language instructions (a validation agent writes behavioral tests that adapt to each submission, rather than fixed hidden tests); bug tasks are sourced from real PRs that needed runtime investigation (logs, profiling, reproduction), not static diffs; and scoring rewards "tasteful" solves against load-bearing but UNSTATED codebase practices. Study it before trusting SWE-bench-style leaderboards for agent readiness — it operationalizes the "beyond static, over-specified tasks" critique (agent-eval-014) into a concrete methodology (validation agent + taste scoring), and shows what evaluating for real-world engineering judgment actually requires
- [DOPD: Dual On-policy Distillation](https://arxiv.org/abs/2606.30626) — Yu, Li, …, Yue, Yan, Wang (16 authors): the artifact that tips on-policy distillation over the trend bar this week (now on-policy-distill-016). On-policy distillation (OPD) trains a student on its OWN sampled trajectories under dense token-level teacher signals — richer than sparse trajectory rewards. DOPD's contribution is a clean warning for anyone reaching for the obvious "give the teacher/student more information" lever: infusing privileged information induces a *privilege illusion* — the student conflates the transferable capability gap it is meant to close with an information-asymmetry gap it can only mimic, never replicate, so the extra signal teaches imitation of un-actionable context rather than real capability. Study it (with the same week's OPID 2606.26790 for skill-conditioned OPD and AsyncOPD 2606.24143 for the async/staleness systems view) as the current state of on-policy distillation as the post-training method for reasoning/agentic models — and for the privilege-illusion failure mode as a concrete design constraint when building distillation pipelines
- [Agentic Abstention: Do Agents Know When to Stop Instead of Act?](https://arxiv.org/abs/2606.28733) — Luo, Wen, Wang; the day's TOP HF paper (109 up). Reframes a deployment failure mode every agent builder hits: knowing when to STOP. Unlike single-turn answer-or-abstain, agentic abstention is sequential — at each turn the agent can answer, abstain, or gather more info, and the need to stop may only become clear after acting — so the metric that matters is not WHETHER an agent can abstain but WHEN. Across web-shopping, terminal and QA (28,000+ tasks, 13 LLM-as-agent systems + 2 scaffolds), some agents never abstain when they should and others burn many wasted tool calls first. Study it before trusting any long-horizon agent loop in production — it names the calibration gap (over-acting / not-stopping) that static leaderboards miss, and is a clean instance of the deployment-grounded agent-eval line the radar tracks (agent-eval-014)
- [Experience Graphs / Trellis: The Data Foundation for Self-Improving Agents](https://arxiv.org/abs/2606.29823) — a 25-author argument that long-horizon agentic work (code, scientific discovery, hardware design) is a new database WORKLOAD: an agent that generates artifacts, runs tools, observes failures, branches and repairs over hundreds of steps produces a structured "experience graph" (executable artifacts, tool outputs, rewards, sibling comparisons, causal lineage) that today's frameworks throw away as JSON checkpoints / session logs — unrecoverable after a crash, un-queryable across users, un-materializable into training data. Trellis treats that graph as first-class, governed, queryable database state. Study it for the systems framing of agent memory/state (vs prompt-stuffing or vector RAG) — the data-management lens that, with the agent-native-memory study and the Always-On Agents survey, is consolidating the agent-runtime-015 axis
