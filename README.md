## Worth studying

- [Direct-OPD: Weak-to-Strong Generalization via Direct On-Policy Distillation](https://arxiv.org/abs/2607.05394) — Shiyuan Feng et al. (10 authors): a practically-motivated post-training recipe for anyone doing RLVR. As models scale, running RL on the target is the bottleneck (many expensive rollouts on a huge model), so run RL on a SMALL cheap model and transfer only the RL-induced policy shift to the strong target. The load-bearing idea: don't distill the weak teacher's final policy (it mixes RL gains with the small model's limits) — compare the post-RL teacher to its own pre-RL reference and use the log-ratio as a dense implicit reward, so only "what RL changed" transfers. A concrete datapoint on decoupling where you PAY for RL from where you APPLY it.
- [Flash-MSA: open-source training kernels for MiniMax Sparse Attention](https://nanduruganesh.github.io/flash-msa/) — a solo, unaffiliated engineer's CuTeDSL kernels billed as "the world's first performant open-source TRAINING kernels for MiniMax Sparse Attention" on Hopper/Blackwell. Frontier models use sparse attention to speed up INFERENCE, but no one had posted code to TRAIN it efficiently; Flash-MSA's design is the study material — block-sparse selection (128-token blocks, only block indices cached to the backward, only the proxy forward stays quadratic), GQA instead of MLA (reproducible for western training stacks), group-wise proxy-head specialization. The kernel engineering behind subquad-attn-012's training side; caveat: solo project, "not an official MiniMax implementation".
- [Colibri: run GLM-5.2 (744B MoE) on a 25 GB-RAM machine in pure C](https://github.com/JustVugg/colibri) — JustVugg (72★): a pure-C, zero-dependency inference engine that streams MoE experts from disk so a 744B model runs on ~25 GB RAM at 0.05–0.1 tok/s cold. An existence proof and design reference for extreme MoE expert-offloading on the CPU-first/on-device axis; caveat: barely-interactive throughput (a capability demo, not a daily driver), solo/community project.
- [UniClawBench: capability-driven eval of proactive agents in live containers](https://arxiv.org/abs/2607.08768) — HKU-MMLab (7 authors): a deployment-grounded agent benchmark that runs agents in LIVE Docker containers scored by fine-grained step-by-step completion checkpoints, and decomposes 400 bilingual real-world tasks by five FOUNDATIONAL model capabilities so a failure points to a capability. Its closed-loop eval (executor + hidden supervisor + user agent) simulates realistic multi-turn feedback without leaking grading criteria. The current methodology for evaluating proactive / real-world agents.
- [Nemotron-Labs-Diffusion: a tri-mode AR + diffusion + self-speculation LM](https://arxiv.org/abs/2607.05722) — NVIDIA (26 authors): the clearest current case that AR and diffusion decoding are complementary rather than rival. One architecture, JOINT AR-diffusion objective, switches among AR, diffusion and self-speculation to sustain throughput; shipped OPEN at 3B/8B/14B (the 8B decodes 6× more tokens/forward than Qwen3-8B → 4× higher throughput on SGLang/GB200). Caveat: throughput vendor-reported, native diffusion serving not yet confirmed in an engine release.
- [OmniOpt: Taxonomy, Geometry, and Benchmarking of Modern Optimizers](https://arxiv.org/abs/2607.04033) — 12 authors (top HF daily paper 07-07, 67 up): a unified survey + benchmark "cookbook" for the 100+ modern optimizers, treating every update as a structured transformation through a five-stage meta-pipeline, then benchmarking under matched budgets. Read it before picking an optimizer for a large training run.
- [Bridging the Gap Between Latent and Explicit Reasoning with Looped Transformers](https://arxiv.org/abs/2606.31779) — Ying Fan, Anej Svete, Kangwook Lee: the clearest answer to "why has latent chain-of-thought underperformed, and can it be fixed?" Latent CoT LOSES to explicit CoT beyond ~1B params and the gap WIDENS with scale; this argues looped / recurrent-depth Transformers are the natural substrate and gives a recipe that closes the gap. The scaling-honest reference for the looped/latent-reasoning line.
- [AI-Infra-Guard: Multi-Layer Agent Red Teaming](https://arxiv.org/abs/2606.31227) — Yong Yang et al. (10 authors): a practical open-source blueprint for the agent-security stack. Its observation is that the attack surface is STRATIFIED (infrastructure, protocol/tool, behavior, model) and no single paradigm covers all layers, so it matches a technique to each: rule-matching over 1,400+ vuln rules, LLM-driven MCP/skill auditing, multi-turn black-box red teaming, a 26+-operator jailbreak harness. A checklist of what each layer needs tested.
- [SkillOpt: Agent skills as trainable parameters](https://www.microsoft.com/en-us/research/blog/skillopt-agent-skills-as-trainable-parameters/) — Microsoft Research: "make the skill file itself trainable." SkillOpt treats the skill file as a trainable parameter OUTSIDE a frozen model and optimizes it as a controlled process (bounded edits, validation gating, rejected-edit feedback). Best-or-tied-best in all 52 eval cells with NO weight updates, and skills transfer across model scales — the weight-free counterpart to compile-behavior-into-adapters.
- [Memora: A Harmonic Memory Representation](https://www.microsoft.com/en-us/research/blog/memora-a-harmonic-memory-representation-balancing-abstraction-and-specificity/) — Microsoft Research: agent long-term memory that decouples WHAT is stored from HOW it is retrieved (lightweight abstractions + cue anchors). New SOTA on LoCoMo and LongMemEval, beating Mem0, RAG and full-context inference while using up to 98% FEWER context tokens — read it before building any long-horizon agent memory layer.
- [PrismML Ternary Bonsai (true 1.58-bit LLMs at 8B/4B/1.7B)](https://prismml.com/news/ternary-bonsai) — a commercial, independent (Caltech-origin) lab shipping a ternary-throughout LLM family: {-1,0,+1} weights in EVERY layer, ~9× smaller memory than 16-bit. The clearest current existence proof of true 1.58-bit models ABOVE the ~2.4B research ceiling; caveat: benchmarks vendor-claimed, download availability unverified.
- [Program-as-Weights (PAW): compiling fuzzy functions into local adapters](https://arxiv.org/abs/2607.02512) — Wentao Zhang, …, Stuart Shieber (Harvard-line): PAW compiles a "fuzzy function" FROM a natural-language spec INTO a compact locally-executable adapter (a 4B compiler on the released 10M-example FuzzyBench emits a PEFT adapter for a frozen model). The "put behavior in weights, not the prompt" alternative to RAG/harness-context.
